# Глоссарий проекта «Автопарк»

## База данных (Database)
Центральное хранилище информации о пользователях, водителях, автомашинах, заказах и начислениях. В проекте реализована как SQLite база данных, содержащая таблицы: USERS, DRIVERS, VEHICLES, ORDERS, EARNINGS, DRIVER_STATS, VEHICLE_STATS, CONFIG.

## Пользователь (User)
Объект, представляющий сотрудника системы. Содержит:
- имя пользователя (username),
- хэш пароля (password_hash),
- роль (role) — администратор (admin) или водитель (driver).
Отвечает за аутентификацию и авторизацию в системе.

## Аутентификация (Authentication)
Процесс проверки логина и пароля пользователя для входа в систему.

## Авторизация (Authorization)
Процесс определения уровня доступа пользователя к функционалу:
- администратор — полный доступ (управление водителями, машинами, заказами, отчёты);
- водитель — доступ только к своим данным и своим заказам.

## Водитель (Driver)
Сотрудник автопарка, управляющий автомашиной. Атрибуты:
- табельный номер (personnel_number),
- фамилия, имя, отчество,
- категория (B, C, D, E),
- стаж работы (experience),
- адрес,
- год рождения,
- фотография (photo).
Водитель, выполнивший заказ, получает 20% от стоимости перевозки.

## Автомашина (Vehicle)
Средство передвижения для перевозки грузов. Атрибуты:
- номер машины (plate_number),
- марка (brand),
- пробег на момент приобретения (mileage_on_purchase),
- грузоподъёмность (capacity),
- фотография (photo).
Каждая машина может участвовать в нескольких заказах.

## Заказ (Order)
Выполненная перевозка груза. Атрибуты:
- дата выполнения заказа (order_date),
- ссылка на водителя (driver_id),
- ссылка на машину (vehicle_id),
- километраж (distance),
- масса груза (cargo_weight),
- стоимость перевозки (cost).
При добавлении заказа проверяется, не превышает ли масса груза грузоподъёмность машины.

## Начисление (Earning)
Запись о начислении водителю 20% от стоимости перевозки. Атрибуты:
- ссылка на водителя (driver_id),
- ссылка на заказ (order_id),
- сумма начисления (amount),
- дата расчёта (calculated_date).
Создаётся автоматически при добавлении нового заказа.

## Статистика по водителю (DriverStats)
Агрегированная информация о работе водителя. Атрибуты:
- общее количество поездок (total_trips),
- общая масса перевезённых грузов (total_cargo),
- общая сумма заработанных денег (total_earnings).
Обновляется автоматически при добавлении каждого заказа.

## Статистика по машине (VehicleStats)
Агрегированная информация об использовании машины. Атрибуты:
- общий пробег (total_mileage),
- общая масса перевезённых грузов (total_cargo),
- общее количество поездок (total_trips).
Обновляется автоматически при добавлении каждого заказа.

## Конфигурация (Config)
Настройки системы, хранящиеся в базе данных. Примеры настроек:
- `driver_percent` — процент от стоимости перевозки, начисляемый водителю (по умолчанию 20),
- `min_driver_experience` — минимальный стаж водителя для приёма на работу,
- `max_cargo_weight` — максимально допустимый вес груза для системы.

## Триггер (Trigger)
Автоматическое действие в базе данных, выполняющееся при вставке, обновлении или удалении данных. В проекте используются триггеры для:
- автоматического начисления 20% водителю при добавлении заказа;
- инициализации статистики при добавлении нового водителя;
- инициализации статистики при добавлении новой машины.

# Дополнительная спецификация проекта «Управление автопарком»

## 1. Производительность
- Система должна обрабатывать до 1000 заказов, 500 водителей и 200 автомашин без заметного снижения производительности.
- Время отклика на запрос аутентификации пользователя не должно превышать 1 секунды.
- Отчёты по водителям и машинам должны формироваться за <2 секунды при объёме данных до 500 записей.
- Выполнение операций INSERT, UPDATE, DELETE должно занимать не более 0.5 секунды.

## 2. Надёжность и отказоустойчивость
- Система должна корректно обрабатывать ошибки ввода данных (отрицательный стаж, неверный формат даты, пустые поля, превышение грузоподъёмности).
- Все ошибки базы данных должны обрабатываться с выводом информативного сообщения пользователю.
- При ошибке подключения к базе данных программа должна завершаться с понятным сообщением, без аварийного останов.
- Транзакции должны обеспечивать целостность данных: при ошибке вставки заказа не должно происходить частичного сохранения.

## 3. Безопасность
- Пароли пользователей хранятся в базе данных в зашифрованном виде (в текущей версии — хэширование).
- Только аутентифицированные пользователи могут получить доступ к функционалу системы.
- Водители могут просматривать только свои заказы и начисления; администратор — полный доступ ко всем данным.
- Доступ к базе данных осуществляется только через приложение, прямое подключение извне не предусмотрено.

## 4. Интероперабельность
- Приложение консольное, работает в среде Linux (Ubuntu) и macOS.
- Используется SQLite3, что обеспечивает кроссплатформенность и отсутствие необходимости в отдельном сервере базы данных.
- Возможна интеграция с другими СУБД (PostgreSQL, MySQL) при минимальных изменениях модуля database.c.

## 5. Пользовательский интерфейс
- Интерфейс консольный, построен на основе текстового меню.
- Понятные подсказки для ввода данных (форматы дат, допустимые значения).
- Для администратора выводятся полные списки водителей, машин, заказов и отчётов.
- Для водителя — доступ только к своим данным, заказам и начислениям.

## 6. Локализация
- Текущая версия поддерживает только русский язык.
- Все сообщения в консоли, названия пунктов меню и подсказки на русском языке.
- Поля ввода принимают русские и латинские символы (фамилии, адреса).

## 7. Аппаратные требования
- Процессор: 1 ГГц или выше.
- ОЗУ: 512 МБ (минимально), 2 ГБ (рекомендуется).
- Место на диске: 100 МБ (для проекта, базы данных и временных файлов).

## 8. Ограничения
- Данные хранятся в файле SQLite (data/autopark.db); после закрытия программы данные сохраняются.
- Одновременная работа нескольких пользователей не поддерживается.
- Нет графического интерфейса; все взаимодействия через консоль.
- При добавлении заказа проверка грузоподъёмности выполняется, но не блокирует возможность создания заказа с весом, равным грузоподъёмности.
- Фотографии водителей и машин хранятся как BLOB, но в текущей версии не отображаются в консоли.

## 9. Журналирование
- Система выводит сообщения об ошибках и успешных операциях в консоль.
- В будущем возможно ведение лог-файлов для аудита действий пользователя (кто, когда и какие операции выполнял).
- Ошибки базы данных логируются с выводом кода ошибки SQLite.

## 10. Расширяемость
- Добавление новых сущностей (например, типов грузов, категорий водителей) возможно без изменения существующих модулей.
- Процент начисления водителю (20%) вынесен в конфигурацию (таблица CONFIG) и может быть изменён без перекомпиляции.
- Можно расширить функционал отчётов (добавить новые виды статистики) через модуль report.c.
- Возможна интеграция с графическим интерфейсом (QT, GTK) с сохранением существующей бизнес-логики.
- Поддержка экспорта отчётов в CSV и JSON может быть добавлена без изменения ядра системы.

## 1.USERS (Пользователи)
#####  Таблица для хранения учетных записей пользователей приложения (диспетчеры и водители).
| Поле | Тип | Описание |
|------|-----|----------|
| **user_id** | INTEGER| Уникальный идентификатор, PRIMARY KEY |
| **username** | TEXT | Логин пользователя, UNIQUE, NOT NULL|
| **password_hash** | TEXT | Хэш пароля, NOT NULL |
| **full_name** | TEXT | ФИО пользователя, NOT NULL |
| **role** | TEXT | Роль: admin (диспетчер), driver (водитель), CHECK |
| **created_at** | TIMESTAMP | Дата создания записи, DEFAULT CURRENT_TIMESTAMP |

## 2.DRIVERS(Водители)
##### Информация о водителях автопарка.
| Поле | Тип | Описание |
|------|-----|----------|
| driver_id | INTEGER | Уникальный идентификатор, PRIMARY KEY |
| personnel_number | TEXT | Табельный номер, UNIQUE, NOT NULL |
| last_name | TEXT | Фамилия водителя, NOT NULL |
| first_name | TEXT | Имя водителя, NOT NULL |
| patronymic | TEXT | Отчество водителя |
| category | TEXT | Категория водителя (B, C, D, E), NOT NULL |
| experience | INTEGER | Стаж в годах, DEFAULT 0, CHECK (experience >= 0) |
| address | TEXT | Адрес водителя |
| birth_year | INTEGER | Год рождения, CHECK (birth_year > 1900) |
| photo | BLOB | Фотография водителя |
| user_id | INTEGER | Связь с учетной записью, UNIQUE, FOREIGN KEY USERS(user_id) |

Индексы:

* idx_drivers_lastname — ускоряет поиск по фамилии водителя

* idx_drivers_personnel — ускоряет поиск по табельному номеру

## 3. VEHICLES (Автомашины)
##### Информация об автомашинах автопарка.
| Поле | Тип | Описание |
|------|-----|----------|
| vehicle_id | INTEGER | Уникальный идентификатор, PRIMARY KEY |
| plate_number | TEXT | Номер машины, UNIQUE, NOT NULL |
| brand | TEXT | Марка автомобиля, NOT NULL |
| mileage_on_purchase | INTEGER | Пробег на момент приобретения в км, DEFAULT 0 |
| capacity | REAL | Грузоподъёмность в тоннах, NOT NULL, CHECK (capacity > 0) |
| photo | BLOB | Фотография машины |

Индексы:

* idx_vehicles_plate — ускоряет поиск по номеру машины

* idx_vehicles_brand — ускоряет поиск по марке


## 4. ORDERS (Выполненные заказы)
#####  Информация о выполненных заказах на перевозку грузов.
| Поле | Тип | Описание |
|------|-----|----------|
| order_id | INTEGER | Уникальный идентификатор, PRIMARY KEY |
| order_date | DATE | Дата выполнения заказа, NOT NULL |
| driver_id | INTEGER | Ссылка на водителя, FOREIGN KEY DRIVERS(driver_id) |
| vehicle_id | INTEGER | Ссылка на машину, FOREIGN KEY VEHICLES(vehicle_id) |
| distance | INTEGER | Километраж (км), CHECK (distance > 0) |
| cargo_weight | REAL | Масса груза в тоннах, CHECK (cargo_weight > 0) |
| cost | REAL | Стоимость перевозки, CHECK (cost >= 0) |

Индексы:

* idx_orders_driver — ускоряет выборку заказов по водителю

* idx_orders_vehicle — ускоряет выборку заказов по машине

* idx_earnings_driver — ускоряет выборку начислений по водителю

* idx_earnings_date — ускоряет выборку по дате расчёта

## Связи между таблицами 
USERS(user_id) <-- DRIVERS(user_id)

DRIVERS(driver_id) <-- ORDERS(driver_id)
DRIVERS(driver_id) <-- EARNINGS(driver_id)
DRIVERS(driver_id) <-- DRIVER_STATS(driver_id)

VEHICLES(vehicle_id) <-- ORDERS(vehicle_id)
VEHICLES(vehicle_id) <-- VEHICLE_STATS(vehicle_id)

ORDERS(order_id) <-- EARNINGS(order_id)

### Описание связей 
* USERS 1:1 DRIVERS — один пользователь может быть привязан к одному водителю (для аутентификации)

* DRIVERS 1:N ORDERS — один водитель может выполнить несколько заказов

* DRIVERS 1:N EARNINGS — один водитель может иметь несколько начислений

* DRIVERS 1:1 DRIVER_STATS — один водитель имеет одну запись статистики

* VEHICLES 1:N ORDERS — одна машина может участвовать в нескольких заказах

* VEHICLES 1:1 VEHICLE_STATS — одна машина имеет одну запись статистики

* ORDERS 1:1 EARNINGS — один заказ генерирует одно начисление водителю

# Функциональные требования проекта «Автопарк»

## 1. Аутентификация и авторизация
Система должна обеспечивать вход пользователей по логину и паролю.
Поддержка двух ролей:
- **Администратор** — полный доступ ко всем функциям системы.
- **Водитель** — ограниченный доступ, просмотр только своих данных и своих заказов.

## 2. Управление пользователями
Администратор может создавать, редактировать и удалять пользователей системы.
Пользователи хранят информацию о логине, хэше пароля, ФИО и роли.

## 3. Управление водителями
Добавление, редактирование и удаление водителей.
Каждый водитель имеет:
- табельный номер (уникальный),
- фамилию, имя, отчество,
- категорию (B, C, D, E),
- стаж работы,
- адрес,
- год рождения,
- фотографию.
Водитель может просматривать только свои данные и свои заказы.

## 4. Управление автомашинами
Добавление, редактирование и удаление автомашин.
Каждая машина имеет:
- номер машины (уникальный),
- марку,
- пробег на момент приобретения,
- грузоподъёмность,
- фотографию.

## 5. Управление заказами
Добавление, редактирование и удаление заказов на перевозку грузов.
Заказ содержит:
- дату выполнения,
- ссылку на водителя,
- ссылку на машину,
- километраж,
- массу груза,
- стоимость перевозки.
При добавлении заказа система автоматически проверяет, не превышает ли масса груза грузоподъёмность машины. Если превышает — заказ не добавляется, выводится сообщение об ошибке.

## 6. Расчёт и учёт начислений водителям
Водитель, выполнивший заказ, получает **20% от стоимости перевозки**.
Система автоматически рассчитывает начисление при добавлении заказа.
Водитель может просматривать только свои начисления.
Администратор может просматривать начисления всех водителей за выбранный период.

## 7. Автоматическое обновление статистики
Система автоматически обновляет статистику при добавлении заказа:
- для водителя: количество поездок, общая масса грузов, общая сумма заработка;
- для машины: общий пробег, общая масса грузов, количество поездок.

## 8. Отчёты и статистика
Система должна предоставлять следующие отчёты:

- **По указанному водителю** — перечень выполненных заказов за указанный период (доступно водителю и администратору).

- **По указанной машине** — общий пробег и общая масса перевезённых грузов (доступно администратору).

- **По каждому водителю** — общее количество поездок, общая масса перевезённых грузов, сумма заработанных денег (доступно администратору).

- **По водителю, выполнившему наименьшее количество поездок** — все сведения о водителе и количество полученных денег (доступно администратору).

- **По автомашине с наибольшим общим пробегом** — все сведения о машине (доступно администратору).

## 9. Ограничения доступа
- **Администратор** — полный доступ ко всем операциям и отчётам.
- **Водитель** — доступ только к своим данным, своим заказам и своим начислениям.

## 10. Валидация данных
Система проверяет корректность вводимых данных при добавлении:
- при добавлении заказа — масса груза не должна превышать грузоподъёмность машины;
- при добавлении водителя — стаж не может быть отрицательным, год рождения должен быть больше 1900;
- при добавлении машины — грузоподъёмность должна быть больше 0, пробег не может быть отрицательным;
- при добавлении заказа — километраж и стоимость перевозки должны быть больше 0.

## 11. Конфигурация системы
Система должна хранить настраиваемые параметры в таблице CONFIG:
- `driver_percent` — процент от стоимости перевозки, начисляемый водителю (по умолчанию 20);
- `min_driver_experience` — минимальный стаж водителя для приёма на работу;
- `max_cargo_weight` — максимально допустимый вес груза для системы.

## 12. Архитектурные требования
- Консольное приложение на языке C.
- Проект многомодульный, с папками: src, include, data, bin, obj.
- Используются отдельные модули для работы с водителями, машинами, заказами, отчётами и базой данных.
- Все операции выполняются через SQLite базу данных.
- Структура проекта соответствует модели КИС (классическая информационная система) с разделением на слои представления (main.c), бизнес-логики (pensioner.c, vehicle.c, order.c, report.c) и доступа к данным (database.c).
